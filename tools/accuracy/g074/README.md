# g074: SightX on sets we may show (rework of PR 130, g068)

PR 130 served 100 dpi images of three harvested Missouri sets' plan sheets on a public route. Those are third-party architects' drawings, kept as local review copies with no republication (tools/corpus/harvest). This rework takes them out and makes the sheet view a tool on the customer's own set.

## 1. Public sheet view: the WeylandAI Building only

/sightx/?set=4847b09e633103f7 opens the WeylandAI Building. This is WeylandAI's own sample bid set (tools/bidset, SAMPLE PROJECT - NOT A REAL BUILDING), opened on its plan sheet A-101 from its g066 placement record:
- 48 OF 48 PLACED in the HUD;
- a ring on every door tag;
- one door card per opening (mark, room, size, hardware group, door and frame type, rating, schedule page, the tag's sheet and position);
- OPENINGS CSV.

How the sheet is served:
- The sheet is drawn in the visitor's browser from the Building's own PDF by the self-hosted pdf.js (/api/hardware-schedule/client-ocr-assets/pdf.mjs, the build SubX reads with).
- No sheet image is served, and nothing comes from a CDN or a third party at request time.
- The PDF ships as the one Data module (weyland-sightx-worker/assets/building/4847b09e633103f7.pdf.bin, 33,257 bytes) at /api/sightx/sheets/4847b09e633103f7/set.pdf.

`tools/accuracy/g068/build-sheets.mjs` builds only sets we authored. Asked for a harvested set, it stops with "is not a set we authored: harvested sets are local review copies and are not published (g074)".

## 2. Your own set: WALK IT IN SIGHTX

**No page hop (review change, 2026-10-11 04:56Z).** WALK IT IN SIGHTX is a button, not a link, and it never replaces a document:
- **Inside the weylandai.com shell's overlay frame:** SubX asks the parent `WeylandShell.open("app", {path})` to open `/sightx/?walk=<session>` in its overlay.
- **As the top document:** SubX opens that path in its own same-origin frame over itself (`#walk-overlay`, `#walk-frame`). It has a CLOSE control. Escape also closes it. Focus moves into the frame, and returns to WALK IT on close. The address never changes.


After a SubX upload, the schedule's actions include WALK IT IN SIGHTX. It links to /sightx/?walk=<session>. In the site shell, SightX opens over the workspace in the same document. It loads three things from the customer's own SubX session:
- GET /doors: the door rows;
- GET /plan: SubX runs readPlan from weyland-shared on the uploaded PDF for the door tags;
- GET /source.pdf: the PDF, from the existing SubX upload store. pdf.js draws it in the browser.

Two things stay as they are:
- POST /api/sightx/openings {doors, plan} joins rows to tags by mark, in schedule order, and returns the openings, placed-of-total and the CSV. It is stateless and stores nothing.
- The PDF never leaves the customer's session and SubX's store.

The CSV columns are: mark, room, size, width_in, height_in, pair, hardware_group, fire_rating, door_type, frame_type, schedule_page, schedule_row, plan_sheet, plan_page, tag_x_pt, tag_y_pt, placed. `schedule_row` is SubX's own row number, as its door list prints it.

## A reader fix the CSV needed

The Building prints PAIR in its door schedule's REMARKS column. SubX's text-layer reader took pair only from a PR prefix on the size or from a pair column, so the four pair openings read as single.

**The fix.** In `doorFromRow`, a REMARKS cell that begins with the word PAIR (or PR) is now read as a pair. On 100A the DOOR TYPES legend shares the line and runs into the cell. The fix is in weyland-subx-worker/assets/client-ocr-src/schedule-text-layer.mjs, with its served .bin twin byte-identical.

**What it changes.** On the Building, reader A's pairs go from none to 100A, 111, 200, 300, which equals truth-doors.json. This is tested in weyland-subx-worker/test/g074-building-pairs.test.mjs. `pair` is not one of the truth harness's compared fields (tools/accuracy/truth/agree.mjs DOOR_FIELDS), so agreement and tiers do not move.

**What it doesn't change yet.**
- The Building's placement record still says pair false for these four. It was built with the old reader and is regenerated by g066's placement run.
- The pair column is right on production only once SubX is deployed.
