## Generic reader changes

- Dimension rereads use the initial crop inset, so retries do not accidentally remove additional source pixels. Nine bounded views include grayscale interpolation and native/upscaled threshold variants. Only accepted, parsed physical values vote; at least two agree, and tied values stay unread. This prevents invalid repeated strings from either suppressing valid agreement or approving one unsupported size. `36"` and `3'-6"` remain different values.
- Identifier rereads include native and reduced views because enlargement can change a glyph. Fifteen bounded views share the existing 2,000-call/60-second page budget. One view trims outer whitespace, retains the original gray glyph pixels and a one-pixel margin, and normalizes the cropped height to 36 pixels with an eight-pixel white border.
- Hardware groups are also reread below 95% measured confidence; their grammar allows letters, leading zeroes, spaces, punctuation and compound codes. There is no numeric identifier whitelist or O/Q, I/L or character substitution.
- Candidates need two actual agreeing reads. Ranking uses the strongest measured supported fit, rather than allowing many weak transformed reads to outvote stronger evidence. Near ties abstain. If the original valid identifier is independently supported by the original/reduced gray views, transformed-only agreement cannot overwrite it. Rereading the same original uncertain text retains its original confidence.
- Source and served grid-reader bytes are identical. App, grid runner and nested import cache versions are `20261009g019r2`. The text reader and workspace behavior are unchanged by this field checkpoint.
